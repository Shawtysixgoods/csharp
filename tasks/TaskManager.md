## Лабораторная работа: Архитектура системы управления задачами с уведомлениями

Целью данной работы является проектирование и разработка консольного приложения на языке C# для управления личными и рабочими задачами. Основной упор делается не на графический интерфейс, а на создание гибкой и надежной программной архитектуры с использованием объектно-ориентированного подхода. Вам необходимо реализовать систему, которая способна обрабатывать различные типы планов, следить за их сроками и своевременно оповещать пользователя, исключая при этом дублирование кода и обеспечивая защиту данных внутри объектов.

В ходе реализации вам необходимо проработать следующие компоненты и механизмы:

*   **Базовая абстракция задачи:** Создайте абстрактный класс, который станет фундаментом для всех типов задач. Он должен содержать общие данные: название, подробное описание, крайний срок (дата и время) и текущее состояние. Его роль — определить «контракт» для всех наследников, включая обязательный метод для проверки, не просрочено ли выполнение.
*   **Специализированные типы задач:** Реализуйте несколько конкретных классов на основе базового. Один должен отвечать за обычные дела, другой — за задачи, которые повторяются через определенное время (например, каждые три дня), а третий — за особо важные поручения, требующие дополнительного подтверждения при их завершении. Здесь важно использовать наследование, чтобы не переписывать общие свойства заново.
*   **Инкапсуляция и валидация:** Все внутренние данные классов должны быть защищены. Доступ к ним осуществляется через свойства. Реализуйте логику проверки: например, нельзя установить крайний срок в прошлом или оставить название пустым. Если данные некорректны, объект должен сообщить об ошибке, а не сохранять неверные значения.
*   **Интерфейс уведомлений:** Опишите интерфейс, который диктует поведение для любых объектов, способных отправлять сообщения. Метод этого интерфейса должен принимать решение: пора ли выводить уведомление на экран в зависимости от текущего времени и установленного срока задачи.
*   **Полиморфная обработка:** В основном классе управления создайте механизм, который хранит список всех задач. Этот компонент должен уметь одной командой запустить проверку уведомлений для всех объектов в списке сразу, независимо от того, является ли задача «разовой» или «повторяющейся».
*   **Исключение дублирования (DRY):** Найдите повторяющиеся операции, такие как вычисление оставшегося времени до дедлайна или специальное форматирование текста для вывода в консоль. Вынесите эти действия в отдельные вспомогательные методы или сервисные классы, чтобы один и тот же код не встречался в разных частях программы.

Приступая к выполнению, сначала спроектируйте схему взаимодействия классов на бумаге или в редакторе, определив, какие методы будут общими, а какие — уникальными для каждого типа задач. Особое внимание уделите работе с системным временем: программа должна корректно сравнивать текущий момент с дедлайном, учитывая даже секунды. Помните, что качественная архитектура позволяет легко добавить новый тип задачи (например, «групповую») с минимальными изменениями в уже написанном коде.
